# Phase 16.9 — The generator takes back its name

> See [How it went](#how-it-went) at the end, which is where the shape it really took is written
> down. Everything above that section is the plan as it was written, including the parts the work
> proved wrong — the prediction next to the outcome is the point.

**Goal:** the crate is `map-gen`, the command is `gen-map`, `cargo test --workspace` and
`doc-check` are green, and every map either draws exactly as it did under the old name or is
`open-plain`/`river-valley`, both untouched.
**Depends on:** 16.8 — the point at which `map-gen` (the name) was free again, with nothing left
in the tree to collide with.
**Size:** S.

## Why now

Because `map-gen2` was only ever a number owed to a sibling that no longer exists. The `2` said
"there is another one of these" the whole time it was true, and phase 16.8 made it false: one
generator, wearing a name that argues there might be two.

## What gets built

### The rename, mechanically

- `map-gen2/` becomes `map-gen/`; its `Cargo.toml` package name becomes `"map-gen"`.
- The workspace `members` list, `xtask/Cargo.toml`'s dependency, and every `use`/path reference
  (`map_gen2::` becomes `map_gen::` throughout `xtask/src/gen_map2.rs`, which is itself renamed to
  `gen_map.rs`, its public function `gen_map2` becoming `gen_map`).
- `xtask/src/main.rs`: `mod gen_map2;` becomes `mod gen_map;`, the `"gen-map2"` dispatch arm and
  usage line become `"gen-map"`.
- `xtask/src/doc_check.rs`: the crate-directory list and the `GENERATORS` array both read
  `"map-gen"` again.

### The one value that actually changes what a seed draws

`dice.rs`'s `SALT` moves from `"brando/map-gen2/v1"` to `"brando/map-gen/v1"` — the same string
the deleted crate used to carry, free again since nothing else in the tree has claimed it. This is
the one edit in this phase that changes what a given seed actually draws, and it is safe only
because nothing checks it: no map committed to `sim-data/maps/` was ever drawn by this crate under
either name (`open-plain` predates it, `river-valley` is hand-drawn), and none of this crate's own
tests pin a specific seed's output against a stored value — every one of them compares two runs of
the *same* seed against each other, which holds regardless of what the salt text is. Changing it
is exactly as safe here as it was unsafe would be inside `sim-core`, and for the same reason
stated in reverse: nothing downstream has frozen a value that depends on it.

### The comments that cited a file by a name it no longer has

Two doc comments in the renamed `gen_map.rs` (`note`'s and `wanted`'s) still say "the same device
`gen_map.rs`'s own `note` uses" — a citation written when this file was `gen_map2.rs` and a
*different*, now-deleted `gen_map.rs` existed to compare against. Once this file becomes
`gen_map.rs` in truth, that sentence would cite itself by name as though it were someone else's
work. Both are reworded to state what they do directly, the same fix phase 16.8 already made to
every other comment caught by the removal.

### The words

`GLOSSARY.md`'s `source`, `strength` and `round` entries name `map-gen2` explicitly; all three
become `map-gen`. No new word, no retired one — the concept did not move, only the crate that
carries it.

## Out of scope

**Any change to the algorithm, its tests, or its CLI shape.** This phase renames identifiers and
one salt; `Source`, `SourceKind`, `DrawInput`, `Drawn`, `Report`, `Places`, `DrawError` and every
function signature keep their names exactly.

**Rewriting `ROADMAP.md`'s `Done` rows or any frozen task's prose.** 16.5 through 16.8 each said
`map-gen2`/`gen-map2` because that was the crate's real name while each was being built — a ledger
entry for a phase that shipped a thing correctly names the thing as it was then. This phase adds
its own row and its own amendments; it rewrites nothing above them.

## Tests

1. ***The test that defines the phase.*** `cargo build --workspace` and `cargo test --workspace`
   succeed with the crate at `map-gen/`, package name `map-gen`, and no `map-gen2` anywhere in the
   workspace graph — the crate's own 31 tests are untouched in content, only in the path they run
   from, and all of them still pass.
2. **`gen-map` draws a valid map.** The renamed command, given a fresh seed and a handful of
   sources, still produces a map that survives `render_map` → `parse_map` → `validate_map` — not a
   comparison against the pre-rename tool (the salt change means a given seed draws differently
   now, on purpose, and that is not a regression to guard against), but a check that the rename
   left the tool working.
3. **`doc-check` still passes**, and its generator-edge check still fires if a `sim-*` crate is
   made to depend on `map-gen` (broken on purpose, put back, the same way 16.5 and 16.8 both
   verified it).
4. ***The test that closes the phase.*** `regen-expected --check` is green before and after —
   nothing this phase touches is reachable from `step()`.

**Done when:** `cargo xtask gen-map` draws a map, `map-gen` is the crate that draws it, and
nothing in the workspace still spells either name with a `2`.

## How it went

**One real bug the plan didn't anticipate: two comments in `gen_map2.rs` were already dangling
before this phase even started.** Phase 16.8's removal of the *original* `map-gen` crate deleted
the old `gen_map.rs`, but two doc comments in `gen_map2.rs` — `note`'s and `wanted`'s — still cited
`gen_map.rs`'s own note/helper by name, as though a different file still existed to compare
against. 16.8's own comment sweep missed them because they don't contain the string `map-gen2` or
`map_gen2` — they cited the *other*, already-gone file by its own name, `gen_map.rs`, which this
phase's own grep for `map-gen2`/`gen-map2`/`map_gen2` would never have caught either. They were
found by directly grepping for `gen_map.rs` once the rename made the coincidence obvious: the file
being renamed *to* `gen_map.rs` was the thing that would have made the citation self-referential
and nonsensical. Both were reworded to state their rule directly, with `note`'s folding the
citation into one paragraph rather than pointing elsewhere.

**The `SALT` change was exactly as safe as the plan argued, and nothing tested that claim wrong.**
No committed map anywhere in `sim-data/maps/` was ever drawn by this crate under either name, and
every one of this crate's own tests compares a seed against itself rather than against a stored
value — so `"brando/map-gen2/v1"` becoming `"brando/map-gen/v1"` changed what a given seed draws
(confirmed by hand: the same seed, size and sources drawn just before and just after the rename
produced visibly different terrain) without breaking anything, exactly as predicted.

**Everything else was mechanical and held on the first pass.** The directory rename, the package
name, the workspace member list, `xtask`'s dependency and front-door file, `main.rs`'s module and
dispatch arm, `doc_check.rs`'s two generator-tracking spots, and `GLOSSARY.md`'s three entries all
changed exactly as the plan described. The generator-edge check was broken on purpose against the
renamed crate (`sim-data/Cargo.toml` given a `map-gen` dependency) and caught it correctly, the
same verification 16.5 and 16.8 both already ran. `cargo test --workspace`, `cargo fmt --all
--check`, `cargo xtask doc-check` and `cargo xtask regen-expected --check` are all green, the last
one unchanged before and after. `cargo clippy -p map-gen -p xtask --all-targets` is clean;
`sim-core`'s pre-existing `WalksToTheEnd` warning still blocks the workspace-wide `-D warnings`
run, unrelated to this phase, as 16.6 through 16.8 all already recorded.
