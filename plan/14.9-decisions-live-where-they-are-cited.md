# Phase 14.9 — The decisions live where they are cited

> See [How it went](#how-it-went) at the end, which is where the shape it really took is written
> down. Everything above that section is the plan as it was written, including the parts the work
> proved wrong — the prediction next to the outcome is the point.

**Goal:** `DECISIONS.md` is gone, every rule it held is stated where it binds, and no citation in the
tree resolves to nothing.
**Depends on:** 14.8, for the constitution to have a task shape to live in.
**Size:** L — the largest mechanical diff the tree has taken, and the smallest behavioural one.

## Why now

The register answers *why is it this way?* for code that already answers it. Across 176 citations on
118 lines in 38 source files there is not one bare `// see A12` pointer: every comment states its
rule in full and wears the id as a trailing label, because the naming rule requires exactly that.
Dropping `(A1)` from the sentence *"Money. A whole number, with no thousandths: the treasury has no
in-game fractions, and using thousandths would halve the useful range for nothing"* costs the reader
nothing at all.

The register's own audit, the day before, found two of its entries had been **pure duplication of the
plan files since the day they were written**, and that neither copy had any mechanism keeping it in
agreement with the other. Five of its twenty-five entries were withdrawn stubs. At 1,199 lines it
costs more to read than it returns.

## What gets built

**The constitution becomes a task.** `D1`–`D7` were taken before the first line of code and have
never been withdrawn; they bind code that does not exist yet — the second civilisation, the real
walkers, the renderer. They move verbatim into a task of their own, which is what they always were:
a record of a moment, frozen. The code goes on citing `D4` by id and never by path, and `doc-check`
resolves those ids against that task instead.

**Every `A<n>` tag leaves the tree.** Thirty-eight source files, one manifest, two tables and a
broken fixture. The rule stays exactly where it is; only the label goes. `D<n>` tags are untouched,
including the seven in `clippy.toml`, which already carry their reason inline.

**Three sentences get rewritten rather than de-tagged**, because in them the id is the subject and
not a label. Two make A11 the evidence for *measure before you optimise*; one attributes a
100%-of-ticks measurement to an entry that was withdrawn. They have to say the lesson and the
measurement without a citation.

**`doc-check` loses one rule and gains two.** The register's status rule goes with the register. In
its place, an `A<n>` appearing anywhere in the sources becomes a failure — so the scheme cannot
half-live — and a slot number cited from a comment has to name a task that exists, which is the gap
14.8 made writable and the decisions review recorded as unwritable before that.

## Out of scope

**The dead ends.** A11 records that an optimisation was measured and found not worth building, and
there is no code for a thing that was never built. It goes, and so do the "how it really went"
divergences. This is a loss, it was chosen rather than discovered, and it is written down here so
that whoever proposes targeted invalidation again knows the measurement once existed.

## What its tests will have to prove

- `grep -rnoE '\bA[0-9]{1,2}\b' --include='*.rs' .` returns nothing.
- A `D<n>` cited from a source resolves against the constitution task, and one that does not exist is
  still a finding.
- A comment citing a slot that names no task is a finding.

## Verification

```sh
cargo xtask regen-expected --check
cargo test --workspace
cargo clippy --workspace --all-targets -- -D warnings
cargo fmt --all --check
cargo xtask doc-check
```

Both benchmark state hashes unchanged. The table edits are comment-only and the dataset hash is built
from parsed values rather than file bytes, so if either hash moves, the edit was not the edit it
claimed to be.

## How it went

**Two thirds of it was mechanical, and the last third was not.** Of 176 citations, 138 were a
parenthetical tag on a sentence that already said everything — ` (A5)`, `, A9)`, `(phase 12, A9)` —
and three substitutions removed all of them across 31 files. The remaining 38 were the interesting
ones, and they fell into three shapes that no substitution could have handled:

- **The id as the subject.** *"`A12` counts capacity in residents"*, *"the trap `A9` announced"*,
  *"it lives exactly as long as `A5`"*, *"the generalisation of `A5`'s lesson"*. Each had to be
  rewritten to say the rule instead of naming it — *"capacity is counted in residents"*, *"the trap
  water-as-coverage always carried"*. These are the sentences that prove the register was still doing
  some work, and it was the smallest kind: supplying a noun.
- **Rustdoc link definitions.** `/// [A13]: crate::data::DifficultyDef` resolved an id to a code item
  and had rustdoc checking it. Renaming the anchor to `[`DifficultyDef`]` keeps the check and loses
  nothing.
- **The checker's own prose and fixtures.** `doc_check.rs` documented the `A` namespace it was now
  banning, and two of its unit tests used a literal `A12` as test data — which the new rule reported
  as a real citation. They are spelled `concat!("A", "12")` now, the same dodge the file has carried
  for the plan path since the check that bans it was written. A checker that has to be exempted from
  its own rule is a checker with a hole; a literal spelled in pieces is not.

**The substitution broke a test, and the test caught it.** One of those fixtures was
`cited_ids("counted on residents (A12)")`, asserting the tokenizer finds `('A', 12)`. The strip took
the `(A12)` out of the *string* and left the assertion expecting it — a test that could only fail. It
did, immediately. Worth recording because it is the one place in this task where a blind edit changed
behaviour rather than prose, and the only reason it was cheap is that the fixture was covered.

**Nothing had to be invented for the dead ends, because they were dropped.** The plan said A11's
measurement would go, and it did — but two sentences elsewhere had made A11 their subject rather than
their citation, and those could not simply lose a tag. `CLAUDE.md`'s first lesson and `bench.rs`'s
doc comment now state the measurement itself: the invalidation was measured true on 100% of ticks at
the reference scale, so there was nothing to skip. That is more useful than the pointer was, and it
is the one place where removing the register made a document say *more*.

**Where the ids went instead of an amendment.** Nineteen tasks carried 78 links to the register.
Repointing them was impossible — there is nothing to point at — so the links were removed and the
visible text was left exactly as written: a frozen sentence still reads *"the decision all of M1
rests on is A12"*, and `A12` now names nothing. Twenty-two near-identical amendment blocks would have
been worse than the problem, so there is one sentence in `CLAUDE.md` instead, saying that an `A<n>`
in a task written before today resolves to nothing and that this is expected rather than broken. The
two **unbuilt** plans that instructed a future implementer to go and update `DECISIONS.md` did get
amendments, because those are instructions rather than records, and following them would have meant
editing a file that is not there.
